# Intelligent Magnet/Torrent Routing for Tauri Desktop App

## Problem

The Tauri app always handles magnet links and .torrent files itself (shows window, adds to desktop engine). Users who only use the Chrome extension (with Tauri installed solely for the system bridge) get forced into the desktop UI.

## Design Principles

- **Don't push users into desktop unnecessarily** — if we know the extension is installed and the user hasn't used desktop for torrents, route to extension
- **Don't route to extension blindly** — if we have no evidence the extension even exists, desktop is the safe default
- **No silent fallback to desktop** — if extension routing fails (extension not responding), show a dialog rather than silently opening desktop

## Routing Modes

Three modes in Tauri `settings.json`: **Desktop**, **Extension**, **Auto** (default: Auto).

### Auto Mode Logic

Read `rpc-info.json` profiles + check runtime state. Decision tree:

1. **Check what's currently active:**
   - Desktop window is visible → route to desktop
   - Live extension profile in rpc-info.json (PID alive, health OK) → route to extension
2. **Neither currently active — check history:**
   - Filter profiles that have download roots (actively configured)
   - Sort by `last_used` descending
   - Route based on most recently used profile's `client_type`
3. **Only extension evidence** (profiles have "extension" in `client_types_used`, no `desktop_ever_used` anywhere) → route to extension
4. **Only desktop evidence** (`desktop_ever_used: true`, no extension in `client_types_used`) → route to desktop
5. **No profiles / no evidence of either** → route to desktop (fresh install, can't assume extension is installed)

Signals:
- `desktop_ever_used: bool` (new field on ProfileEntry) — set when user adds first torrent via desktop UI
- `client_types_used: Vec<String>` (new field) — accumulates all client types that ever connected ("extension", "tauri")
- `download_roots` presence + `last_used` timestamp — indicates an actively configured, recently used profile
- Tauri window visibility — runtime check via `app.get_webview_window("main").is_visible()`
- Live extension profile — runtime check via rpc-info.json PID + health endpoint

## Security: Add Token

Any website can navigate the user to `https://new.jstorrent.com/launch#magnet=...`. Since launch.html runs on a trusted `externally_connectable` origin, it can message the extension — creating a drive-by torrent addition vector.

**Solution:** `rpc-info.json` includes an `add_token` field (random string, generated once on first host startup). Tauri and the extension both have access to it. The token is included in launch URLs and validated by the extension before acting on any magnet/torrent payload.

- The hash fragment (`#...&token=SECRET`) never leaves the browser — not sent in HTTP requests or referrer headers
- Only processes with local filesystem access (Tauri, native host) can read the token
- Static token (no rotation needed) — if an attacker can read local files, they have bigger problems

**Fallback without token:** If `add_token` is missing from the URL (e.g. someone shares the launch URL, or old Tauri version), launch.html shows a click-to-confirm prompt before forwarding to the extension. This makes the URL safely shareable while still preventing automated drive-by.

### Token field in rpc-info.json

```json
{
  "add_token": "random-base64-string",
  "profiles": [...]
}
```

Generated by the native host on first startup if not already present. Persisted across restarts.

## Delivery Mechanisms

### Magnets → Extension
Open browser to `https://new.jstorrent.com/launch#magnet=ENCODED&token=ADD_TOKEN`. Launch page forwards magnet + token to extension via `chrome.runtime.sendMessage`. Extension validates token against rpc-info.json value (known via bridge), then creates `MagnetAdded` event.

### Torrent Files → Extension
Open browser to `https://new.jstorrent.com/launch#torrent=ENCODED_PATH&token=ADD_TOKEN`. Launch page forwards path + token to extension. Extension validates token, reads file contents via new `readTorrentFile` host protocol operation (validates path ends with `.torrent`), then adds torrent.

### No Token (drive-by protection)
Launch page detects missing or invalid token. Instead of auto-forwarding, shows a confirmation prompt:
> "Add this torrent to JSTorrent?"
> [magnet/torrent info]
> **[Add Torrent]** [Cancel]

On click, sends the message to the extension without a token. Extension accepts tokenless messages (launch.html already showed confirmation prompt to user).

Note: The launch URL is not meant to be shared — the extension auto-closes the tab on success. The no-token prompt exists purely to block automated drive-by from malicious sites navigating to `launch#magnet=...`.

### Timeout / Extension Not Found
If extension doesn't respond (wrong Chrome profile, uninstalled, etc.), the launch page itself shows an error with options (install extension, try again). For the file path case, the launch page can't do anything with the path alone — it's a pointer to a local file. We should also show a native Tauri dialog after X seconds if the extension hasn't come online to handle the queued deep links.

### 7. `extension/src/sw.ts` — Accept magnet/torrent in launch-ping
